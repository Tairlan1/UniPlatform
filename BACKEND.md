# Бэкенд (реальный Shyn API)

`api_analyze.py` НЕ хранится в этом репозитории — он требует Python-модули
(`ai_detector.py`, `train_model.py` и др.) и обученные модели
(`model/`, `model_ai_detector/`), которые есть только в репозитории `Shyn`.

## Как запустить реальный анализ локально

1. В репозитории **Shyn**:
   ```bash
   pip install flask flask-cors --break-system-packages
   python3 api_analyze.py
   ```
   Поднимет сервер на `http://127.0.0.1:5001`.

2. В этом репозитории (**UniPlatform**):
   ```bash
   npm run dev
   ```
   Vite поднимется на `http://localhost:5173`, CORS на бэкенде уже открыт.

Если сервер Shyn не запущен, вход под аккаунтом любого из пяти
"авторов-студентов" (a.doyle / e.poe / h.wells / j.london / m.twain) при
сдаче задания покажет понятную ошибку соединения — обычный студент
(n.akhmetov) при этом продолжит работать на моке, как и раньше.

## Через Docker (рекомендуется для развёртывания в вузе)

В репозитории **Shyn**:
```bash
docker compose up -d --build
```
Поднимет и веб-интерфейс (`localhost:5000`), и REST API (`localhost:5001`)
из одного образа. Данные сдач (SQLite) переживают пересборку/перезапуск
контейнера — хранятся в volume `shyndyq-data`.

В этом репозитории (**UniPlatform**):
```bash
VITE_SHYN_API_BASE=http://<адрес-сервера-Shyn>:5001 docker compose up -d --build
```
**Важно:** `VITE_SHYN_API_BASE` подставляется на этапе СБОРКИ образа (так
устроен Vite), не при запуске — если адрес API сервера меняется, нужно
пересобрать образ (`--build`), а не просто перезапустить контейнер.

⚠️ Docker-конфигурация написана, но не проверена реальной сборкой (в
среде разработки не было доступа к Docker) — при первом запуске у себя
обязательно проверьте `docker compose build` и сообщите, если что-то не
соберётся.
